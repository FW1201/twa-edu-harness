# Agent Note: 課綱查詢以 (領域, 代碼) 為鍵，歧義時明確報錯

Status: implemented

## Problem

擴充到 5 個領域後才發現：**學習表現與學習內容的代碼不帶領域前綴**，
跨領域必然撞號。實測有 **268 個代碼重複**：

| 代碼 | 國語文 | 英語文 |
|---|---|---|
| `1-Ⅱ-1` | 聆聽時能讓對方充分表達意見。 | 能聽辨26個字母。 |
| `Aa-Ⅱ-1` | 標注注音符號的各類文本。 | 字母名稱。 |

原本的 store 只用代碼當鍵，**後載入的領域會靜默覆蓋前面的**。
查 `1-Ⅱ-1` 會拿到英語文的敘述（因為英語文排在最後），
而呼叫端以為那是國語文的。

## Decision

以 `(領域, 代碼)` 為鍵。`get(code, domain=None)`：

- 有指定領域 → 精確查詢
- 未指定且只有一個候選 → 回傳它
- 未指定且有多個候選 → 丟 `AmbiguousCode`，列出候選領域，**絕不任選一個**

MCP 的 `curriculum_get` / `curriculum_verify` 都加了 `domain` 參數，
歧義時回傳 `ambiguous: true` 與候選清單，並在訊息中明說
「不要自行選一個」。

## 為什麼不能靜默選一個

這是最糟的失敗模式：回傳的敘述**看起來完全正常**——格式對、是真的領綱原文、
長度合理——但屬於另一個領域。使用者沒有任何線索察覺，然後把它寫進教案。

比起「查無此代碼」，一個屬於錯誤領域的正確敘述更難被發現。

## 對 gate 的影響

`verify_curriculum_codes.py` 原本就要求檔案標注 `<!-- curriculum-domain: X -->`
才比對無前綴的代碼——當初是為了避免誤判，現在這個標記正好提供查詢所需的領域。

## Consequences

負面測試必須限定領域。`Da-Ⅳ-1` 不存在於國語文，但在社會與自然科學都是合法代碼；
`7-Ⅳ-1` 不存在於國語文（學習表現只有 1–6 類），但英語文有第 7 類。
這些案例本身就是「代碼必須帶領域才有意義」的最佳例證，已寫成測試。
