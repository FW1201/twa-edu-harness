# Agent Note: 九大領域全覆蓋與三種抽取策略的邊界

Status: implemented

## Problem

從 5 個領域擴充到 9 個。剩下四個（藝術、健康與體育、綜合活動、科技）
各自又帶來新的版面與代碼格式問題。

## Decision

三種抽取策略維持不變，但擴充 `tables-split` 的適用範圍（同時支援兩種儲存格形態），
並新增兩個 profile 選項：`continuations`（跨頁指標）與 `lineFallback`（表格辨識遺漏）。
素養抽取新增跨頁承接。每個領域一份 profile，檔名必須等於 prefix。

## 四個領域各自的狀況

| 領域 | 新問題 | 處理 |
|---|---|---|
| 健康與體育 | 第五學習階段的表格**代碼獨立一格**，敘述在同列後方，`tables-split` 只認「同格內接續」 | 擴充 `tables-split` 同時支援兩種儲存格形態 |
| 藝術 | 學習內容用中文科別前綴（`音E-Ⅱ-5`）；素養列被頁面切斷，前頁只留代碼 | 專屬 pattern；素養抽取新增跨頁承接 |
| 綜合活動 | 學習內容前綴是科目簡稱（`家Aa-Ⅳ-1`），且 PDF 中簡稱與代碼之間有空白 | 前綴**限定為 家童輔生涯**，不能用「任意中文字」 |
| 科技 | 只有國中以上（素養表少一欄）；一列沒被 pdfplumber 辨識為表格 | 素養表欄數放寬；新增 `lineFallback` |

## 兩個「差點掩蓋錯誤」的陷阱

**① 寬鬆前綴會製造幻影代碼。** 綜合活動若用 `[一-鿿]?` 當前綴，
「日常**生**活」被欄位切斷後會與真代碼相黏，產生假的 `生Bc-Ⅱ-1`。
完整性檢查於是報告「漏抓」，但真代碼 `Bc-Ⅱ-1` 其實已正確抽取。

**② 為了消除誤判而加的過濾器，會掩蓋真實遺漏。** 我一度加了
「代碼前方緊接中文字就跳過」的規則，結果把科技真正遺漏的 `設k-Ⅳ-1`
（前方是「日常生活的」）也濾掉了——檢查通過，但資料是錯的。

正確做法是讓**完整性檢查與抽取器讀同一個來源**（走表格的策略就掃表格儲存格），
再另外把「頁面文字看得到、但不在最終資料中」的代碼列為警示。
擋不擋是一回事，**看不看得到是另一回事**。

## Consequences

九個領域共 3460 筆，跨領域重複代碼從 268 增至 496——查詢一律要帶 `domain`。

profile 檔名必須等於 `prefix`，建置時會檢查（科技一度是 `科技.yml` / prefix `科`）。
