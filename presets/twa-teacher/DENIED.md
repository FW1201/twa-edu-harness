# twa-teacher 刻意不給的能力

每一項都被考慮過並否決。**要加回來之前先讀這裡。**

把否決寫進檔案，而不是留在腦袋裡——否則三個月後有人會覺得「這個開著比較方便」
然後打開它，而當初否決的理由已經沒人記得。

---

## `runtime-self-modify`

對執行中的 runtime 求值任意程式碼。**等同 shell 存取，且沒有審核點。**

教師使用者無法評估這個風險。他們判斷不了「讓 AI 修改自己」意味著什麼，
而一旦出事，損害的是他們的備課檔案與學校電腦。

需要這項能力的人請切換到專門的開發者 preset，不要在教師 preset 開。

## `subagent`

委派工作給子代理。

教案生成是線性工作流：確認需求 → 收集資訊 → 產出文件。沒有可平行化的部分。
而 token 成本對教師是不透明的——他們不會預期「幫我寫個教案」會同時跑起五個代理。

**例外**：`tw-edu-citation-checker` 的批次查核（3 筆以上引用）確實會用到
`citation-checker-worker`。那支技能屬於 `twa-researcher` preset，
不在教師 preset 的範圍內。教師若真的需要查核文獻，切換 preset。

## `persistent-terminal`

維持有狀態的終端機工作階段。

所有文件生成腳本都是一次性呼叫（`python generate_x.py --output y.docx`），
不需要維持 shell 狀態。關掉可縮小攻擊面。

`shell` 能力已經足以執行這些腳本。

## `plan-mode`

計畫模式與執行模式的切換。

對教師是額外的認知負擔——他們要先理解「這兩個模式差在哪」才知道自己在哪個模式。
而且功能重疊：技能本身已有引導式資訊收集流程（`shared/guided-collection.md`），
那就是教師版的「先計畫再執行」。

## `lsp`

語言伺服器（程式碼分析）。

本 preset 不做程式開發。

**例外**：`tw-edu-mini-app` 會產生 React 程式碼，但它只需要**寫檔**，
不需要分析既有程式碼。`file-write` 已經足夠。
