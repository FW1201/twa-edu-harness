# 課綱查核協議

> 所有會寫出 108 課綱代碼的技能都必須遵守本協議。

## 為什麼需要這件事

課綱代碼原本寫在技能的 `references/` markdown，由模型讀進 context 再寫出來。
沒有任何方式能驗證。

2026-09-05 實測 `tw-edu-lesson-plan-108` 產出的教案，抽驗 10 筆課綱對應：

| 結果 | 筆數 |
|---|---|
| 代碼根本不存在（如 `語-J-B1`，正確前綴是 `國-`） | 4 |
| 代碼存在，但敘述與領綱不符 | 6 |
| 完全正確 | **0** |

教案會被送交課發會。一個看起來正確但不存在的代碼，會讓教師在會議上出糗。

## 正確做法

### 情境 A：有 `twa-curriculum` MCP（建議）

**寫進文件之前，把每一個代碼都送查核。**

```
curriculum_verify(codes: ["國-J-B1", "5-Ⅳ-2", "Ab-Ⅳ-1"])
```

- `allValid: true` → 直接使用回傳的 `description`，**不要改寫敘述**
- `invalidCodes` 非空 → 不要硬湊。改用 `curriculum_lookup` 以關鍵詞找正確代碼：

```
curriculum_lookup(domain: "國語文", level: "J", kind: "performance", keyword: "閱讀")
```

三個可用工具：

| 工具 | 用途 |
|---|---|
| `curriculum_get` | 依代碼取單一指標的法定敘述 |
| `curriculum_lookup` | 依領域 / 階段 / 類型 / 關鍵詞找代碼 |
| `curriculum_verify` | 批次查核，產出前的最後一道關卡 |

### 情境 B：沒有 MCP（純 Claude Code，尚未安裝）

可以繼續參考 `references/` 的課綱資料，**但必須在產出中標注**：

> ⚠️ 本文件的課綱代碼未經查核。請對照貴校使用的領綱版本確認後再送出。

並且遵守下面這條。

## 不確定就不要寫

**寧可留白，也不要編一個看起來正確的代碼。**

不確定時寫：

> （此處建議對應學習表現，請依貴校使用的領綱版本確認代碼）

這比一個假代碼有用得多——教師看得出來要自己填，而不是以為已經填好了。

## 代碼格式速查

| 類型 | 格式 | 範例 |
|---|---|---|
| 核心素養（國中小） | `<科目>-<階段>-<項目>` | `國-J-B1` |
| 核心素養（高中） | `<科目>S-U-<項目>` | `國S-U-B1` |
| 學習表現 | `<類別數字>-<學習階段>-<序號>` | `5-Ⅳ-2` |
| 學習內容 | `<類別字母>-<學習階段>-<序號>` | `Ab-Ⅳ-1` |

教育階段：E 國小 / J 國中 / U 高中。
學習階段：Ⅰ 國小低年級 / Ⅱ 中年級 / Ⅲ 高年級 / Ⅳ 國中 / Ⅴ 高中。

⚠️ **科目縮寫容易寫錯**：國語文是 `國`，不是 `語`（`語文` 是領域名，代碼用科目名）。
